# 日本航司航班号命名范式（flight_numbering）

> 日本国内线航班号的编号规律：**奇偶 = 走向**、**一条航线一个号段**、**百位数编码地区**（JAL 最规整）。
> 数据来源：FlightAware findflight 实测，2026-10-17 采集约 145 个航线方向、1,628 个真实航班。覆盖羽田 ↔ 45 个机场，以及大阪 / 名古屋 / 福冈 / 札幌 / 那霸 / 成田之间的主要航线。空号率另用 FlightAware 航班号页逐号核验。
> 上游：[../SKILL.md](../SKILL.md)。机器可读副本：项目根 `flight_blocks.json`，由 `tools/build_flight_blocks.py` 生成；程序里的用法见 `dispatcher/airlines.py` 的 `callsign_style`（F30）。

> ⚠️ 这是**统计规律**，每个航季（3 月底 / 10 月底换季）会有局部变动。某个号此刻是否真实存在，仍以 FlightAware 逐号核验为准。

## 一、奇偶 = 走向（几乎 100%，跨所有航司）

- **离开东京方向为奇数（下り），朝东京方向为偶数（上り）**，沿用日本铁路的下り / 上り习惯。具体判定分两步：
  1. **四个始发枢纽先比**：东京（羽田 / 成田 / 茨城）> 大阪（伊丹 / 关西 / 神户）> 名古屋（中部 / 小牧）> 福冈。从等级高的一端出发为奇数。
  2. **其余机场——包括札幌、那霸——按离东京远近**：远的一端是「下」，飞往它为奇数。札幌、那霸是线路的**远端**，不是枢纽。
- 全量校验（311 对 AIP 航线、1,978 个号，2026-10-17）：**98.7%**。

| 例 | 号码 |
| --- | --- |
| 羽田→伊丹 / 伊丹→羽田 | JAL101…139 / JAL102…138 |
| 伊丹→仙台、中部→札幌、福冈→那霸 | 均为奇数（枢纽出发） |
| **福冈→札幌** | **各家航司都是奇数**（福冈是枢纽） |
| 仙台 / 广岛 / 松山→札幌，熊本 / 松山→那霸 | 奇数（飞往远端） |
| 札幌→那霸、那霸→石垣 / 宫古、鹿儿岛→奄美 | 奇数（离东京更远的一端） |

- **航司例外**：
  - **Peach 以大本营关西为上位**：关西→成田为奇数（MM307…）、成田→关西为偶数。捷星以成田为大本营，仍是成田→关西为奇数。
  - **天马把茨城当东京**（茨城→福冈 / 那霸为奇数），但**不把神户当枢纽**（仙台→神户为奇数）。
- **剩下的 1.3%**：
  - 札幌出发的道内 / 近距离线由札幌当枢纽：JAL 札幌→青森 / 花卷（28xx，札幌基地的子公司执飞），ANA 札幌→函馆。FlightAware 按市场航司记号，数据里分不出是哪家执飞。
  - 离岛线由岛上枢纽出发：奄美→喜界、出云→隐岐。
  - ANA 小松↔福冈；以及调机号（ANA9065、JAL8121、SKY7025）、非航司代号（MFX80 等公务机）。

## 二、一条航线一个号段，时刻越早号越小

- 每条航线（同一航司）占一段连续号码：去程用奇数、回程用偶数，**按当天起飞时刻递增**，首班拿该段最小的号。
- JAL 的常见写法：号段基数为偶数 N，**上り用 N, N+2…，下り用 N+1, N+3…**。

  | 航线 | 上り / 下り 首班 |
  | --- | --- |
  | 札幌 | 500 / 501 |
  | 那霸 | 900 / 901 |
  | 鹿儿岛 | 640 / 641 |
  | 青森 | 140 / 141 |

- 号段之间有间隔，**号段内部也有空洞**：减班后号码停用或预留，例如 ANA 宫崎段 602–618 内的 606/607/611/615/616 都是空号。
- 乱序的例外多来自加班机，以及改时刻后沿用了旧号。
- **ANA Wings（AKX）执飞的航班用 ANA 号段里的号**（羽田→伊丹 25/31/33/37 夹在 ANA 11–41 里），共用同一号码空间。

## 五、加班 / 地方 / 子公司 / 4 位号

- **9xx = 干线加班机**：ANA 985–996、JAL 987/988/995/998、SKY 914–974。
- ANA 1xxx = ANA Wings 地方网络与加班：福冈→那霸 1200s、伊丹→松山 1630s、那霸→离岛 1720–1781、羽田→八丈岛 1891–1896。
- ANA 9xxx、AKX 5xxx、Peach 6xxx、捷星 7xxx = 临时加班 / 调机。

## 七、空号在哪里（模拟呼号选号的依据）

| 实测 | 空号率 |
| --- | --- |
| 均匀随机抽 10–999：ANA / JAL / SKY / APJ / JJP / SFJ·ADO·SNJ | 2.5% / 30% / 40% / 50% / 60% / 85% |
| **ANA 600–699 全扫** | **6/100**（600、606、607、611、615、616） |
| **JAL 500–599 全扫** | **17/99**（532、534–538、546–549、559、561、568、571、580、582、583） |
| 现行均匀抽号（20 组随机机场）：每抽一个号撞上真号 | 78%（ANA 92%、JAL 64%、廉航约 30%） |

- **号段没满，空号就在空洞里**：只要锁定对口百位、奇偶按走向，再**按确切号码**扣掉实测出现过的真号，剩下的候选通常只有 9–20 个：
  - ANA 6xx 奇数：剩 9 个，其中 3 个空号（33%，盲抽约 5%）；
  - JAL 5xx 奇数：剩 16 个，其中 8 个空号（50%）。
  - 候选比核验预算还少，等于穷举——只要该百位还有空号就必然找到。
- ⚠️ **不能按区间扣**：空号常在号段内部（ANA 606–616 就在 602–618 之内），按 [min, max] 扣会把它们一并扔掉。
- ⚠️ 只锁百位而不扣真号会更糟：真号恰恰扎堆在对口百位里（JAL 均匀抽 5xx / 6xx / 9xx 都是 0/4）。

## 八、在本项目里的用法（F30）

- `airlines.direction_parity`：奇偶按第一节的两步规则判定（含 Peach / 天马的航司覆盖）。改了规则后运行 `python tools/build_flight_blocks.py --revalidate` 即可离线重验——表里的号码按方向分存（down / up）。
- `airlines.callsign_style`：先锁定「对口百位」。依次放宽匹配：（上位端城市类别, 下位端地区）→（任意, 地区）→（类别, 任意）；只取同类航线用得最多的百位，零星沾到的不锁。再按 `flight_blocks.json` 精确扣掉已知真号。
- `airlines.pick_sim_callsign(style=…)`：先在锁定百位里查，再查同号段其余号，再降级到 4 位号（同样按范式）。是否「已核验」只认 FlightAware 的逐号结论。
- 换季后在项目根运行 `python tools/build_flight_blocks.py` 重新生成号段表。
